## 类图与活动图追溯

类图保留用户、设备、设备使用申请、设备权限关联、操作日志和故障工单六个分析类。用户通过角色上下文体现管理员继承实验人员用例关联，运维人员的关联单独保留。现行分析方案中，每次申请、每条授权和每条设备操作日志各对应一个主体和一台设备。一条工单关联一台设备，人工报修可关联报修人，监测建单无报修人。多重性是分析设计，具体字段与约束仍待明确。

## 重新生成

```bash
python docs/report-build/gen_models.py
cd docs/models
for name in class-diagram activity-uc2-operate activity-uc9-monitor activity-uc11-ticket-ai; do
  drawio -x -f png --scale 1.5 --border 10 -o "$name.png" "$name.drawio"
done
```

改动上述四张图源后重导对应 PNG，再构建报告。脚本生成的 `docs/report-assets/` 为中间产物，可在构建完成后清理。

`gen_models.py` 内置入边和出边检查，注释不参与判定；保存每张图时还会校验所有连线都绑定了 `source`/`target`，且端点是图中已有的顶点。端点通过 `exit/entryX/Y` 固定在顶点轮廓上，因此在 draw.io 中拖动元素时连线会跟着移动。交付时另核对从初始节点能否到达每个活动、互斥流是否经过合并、守卫是否符合用例条件。序列图与通信图共用 `docs/report-build/scenes.py` 的消息清单，与报告正文同源。

## 约定

- 序列图与通信图必须一一对应：编号集合、方向、条件范围相同；回复类消息（返回/展示/提供）用虚线，
  调用保持实线；条件消息只在 `opt` 框内。
- 所有连线必须绑定端点，不再用 `sourcePoint`/`targetPoint` 画无连接的坐标线。
- 活动图分支汇合要加合并节点，终止节点用 UML 牛眼。
- 状态图只画稳定状态，转换写「事件 [条件]」；无终止状态时须在图注说明原因。
- 构件按职责划分，交付图只写候选部署，不确认端口、云厂商、数据库或容器。
- 未确认内容一律标「待明确」，不得为了让图完整而编出阈值、状态集或审批流。
- AI 只是外部建议来源，不执行设备动作；自动建单不连到 UC10。
